# OpenRGB integration (planned)

Goal: native OpenRGB support for the K596 (MosArt, `062A:8519`), submitted upstream as a merge
request to https://gitlab.com/CalcProgrammer1/OpenRGB.

## Controller design

OpenRGB device support consists of a low-level controller (USB I/O) and an `RGBController`
(zones, LEDs, modes), registered by a detector.

| Part | Plan |
|---|---|
| Detector | `REGISTER_HID_DETECTOR_IPU("Redragon K596", DetectRedragonK596, 0x062A, 0x8519, 0, 0xFF19, 0xFF19)` (interface 0, usage page / usage `0xFF19`) |
| `RedragonK596Controller` | `hid_write` of output report `0x08` (64 bytes), wait for the echo on `hid_read` before the next command |
| Direct mode | `08 91` on init, `08 93 group col 00 R G B` per LED, `08 92 00 00 00 R G B` fill, `08 90` on close |
| Zones | one matrix zone (keys, layout from the LED map in [PROTOCOL.md](PROTOCOL.md)) |
| Hardware modes | later: onboard effects via the settings block (`08 21` / `08 05 00 00 18 ...` / `08 22 00 00 02`), written only on mode change because settings writes go to flash |

## Things to solve

1. **Speed.** ~8 ms per command means OpenRGB's usual "send all LEDs every update" would be
   ~1.3 fps. Port the plugin's approach: track what was last sent (or read back feature `0x13`),
   send a fill when most keys share a color, then only the keys that changed, within a time budget
   per `DeviceUpdateLEDs()` call.
2. **White held keys on stock firmware 1.04.** Read back `0x13` periodically and repaint keys that
   differ, or document that firmware 1.05 is recommended.
3. **Model check.** Verify the firmware ID / version (USB `bcdDevice` 0x0104 or 0x0105) so other
   K596 hardware (Sonix, Sinowealth) is never driven with this protocol.
4. **Wireless** (`062A:38B3`, interface 1, `0xFF41`) once [WIRELESS.md](WIRELESS.md) is resolved.

## Submission checklist

* Controller + RGBController + detector, following an existing Redragon / HID keyboard controller
  in the OpenRGB tree as a template.
* Protocol summary in the merge request description (link to this repo).
* Tested on Windows and Linux (udev rule for `062A:8519` is generated by OpenRGB automatically).
